# Обновления Orex из приложения

Orex использует два независимых канала обновлений:

- `stable` — основная установка для ежедневного использования;
- `debug` — параллельная dogfood-установка для тестирования новых сборок и
  самого механизма обновления.

Каналы имеют разные идентификаторы приложения и разные папки на сервере.
Обновление Orex Debug не может заменить установленный Orex Stable.

## 1. Единственный источник версии

Версия и номер сборки задаются только в `pubspec.yaml`:

```yaml
version: <version>+<build>
```

Flutter автоматически переносит их в Android и Windows metadata. Клиент читает
установленную версию через `PackageInfo`, поэтому в коде updater нет номера
релиза, который нужно менять вручную.

Имена папки и установщиков на сервере должны использовать то же значение из
`pubspec.yaml`. Не передавайте отдельные `--build-name` или `--build-number` в
обычной release-сборке.

Для PowerShell значение можно прочитать так:

```powershell
$VersionMatch = [regex]::Match(
  (Get-Content pubspec.yaml -Raw),
  '(?m)^version:\s*(\d+)\.(\d+)\.(\d+)\+(\d+)\s*$'
)
if (-not $VersionMatch.Success) {
  throw 'В pubspec.yaml ожидается version: X.Y.Z+N'
}

$VersionName = '{0}.{1}.{2}' -f `
  $VersionMatch.Groups[1].Value, `
  $VersionMatch.Groups[2].Value, `
  $VersionMatch.Groups[3].Value
$BuildNumber = $VersionMatch.Groups[4].Value
$Release = "$VersionName+$BuildNumber"
```

## 2. Сервер обновлений

В `docker-compose.web.yml` добавлен сервис `orex-updates`. Он подключает локальную
папку `updates` только для чтения и автоматически формирует `latest.json`.

Один раз создайте каталоги каналов:

```bash
mkdir -p updates/stable updates/debug
docker compose -f docker-compose.web.yml up -d orex-updates
```

Стандартный адрес клиента:

```text
https://orex.vasys.ru/updates/<channel>/latest.json
```

Для другого домена передайте общий базовый URL при сборке:

```text
--dart-define=OREX_UPDATE_BASE_URL=https://example.org/updates/
```

## 3. Публикация релиза

Внутри нужного канала создайте папку с именем `<version>+<build>` и загрузите
установщики. `notes.md` необязателен.

```text
updates/
  stable/
    <version>+<build>/
      Orex-Setup-<version>+<build>.exe
      app-arm64-v8a-<version>+<build>.apk
      app-armeabi-v7a-<version>+<build>.apk
      notes.md
  debug/
    <version>+<build>/
      Orex-Setup-<version>+<build>.exe
      app-arm64-v8a-<version>+<build>.apk
      app-armeabi-v7a-<version>+<build>.apk
      notes.md
```

JSON вручную не редактируется. Сервер публикует только папку, где присутствуют
все три ожидаемых установщика, выбирает наибольший числовой `build` и возвращает
размеры файлов. Неполностью загруженная папка не становится последним релизом.

Для безопасной загрузки сначала используйте временное имя:

```text
<version>+<build>.uploading
```

После загрузки всех файлов переименуйте папку в `<version>+<build>`. Каталоги,
которые не соответствуют этому формату, сервер игнорирует.

Проверка результата:

```bash
curl -fsS https://orex.vasys.ru/updates/stable/latest.json
curl -fsS https://orex.vasys.ru/updates/debug/latest.json
```

`build` должен увеличиваться внутри каждого канала. Stable и debug могут иметь
разные текущие номера сборок.

## 4. Проверка обновления через Debug-канал

1. Укажите в `pubspec.yaml` тестовую версию с меньшим номером сборки.
2. Соберите и установите Orex Debug по инструкции нужной платформы.
3. Увеличьте только `build` в `pubspec.yaml`.
4. Снова соберите Debug и опубликуйте файлы в
   `updates/debug/<version>+<build>/`.
5. В установленном Orex Debug откройте
   `Настройки → О приложении → Проверить обновления`.

Stable-приложение при этом остаётся установленным и использует только
`/updates/stable/`.

## 5. Поведение клиента

После восстановления авторизованной сессии Orex неблокирующе проверяет
обновления не чаще одного раза в шесть часов. Ручная проверка всегда доступна в
`Настройки → О приложении`.

Когда найдена более новая сборка:

1. верхняя плашка показывает `Доступна новая версия`;
2. нажатие открывает диалог с `notes.md` и размером установщика;
3. кнопка `Установить` скачивает файл во временный системный каталог;
4. тот же диалог показывает записанные байты и прогресс;
5. Windows запускает Inno Setup, Android — системный установщик пакетов.

При первом самостоятельном обновлении Android может открыть системный экран
`Установка неизвестных приложений` для текущего Orex-канала. Разрешите установку,
вернитесь в оставшийся открытым диалог и снова нажмите `Установить`. Загруженный
APK сохраняется в кэше приложения для этой повторной попытки.

Закрытие верхней плашки скрывает только конкретный `version + build`. Следующая
сборка снова будет показана. Во время активного звонка плашка обновления не
отображается.

## 6. Границы безопасности

Первая версия updater намеренно не требует вручную подготовленного SHA-256.
Клиент принимает только HTTPS-ссылки внутри `OREX_UPDATE_BASE_URL`, отклоняет
редиректы на другой host и сверяет число скачанных байтов с размером от сервера,
если размер известен.

Android-обновление по-прежнему требует тот же application ID и тот же signing
key, что у установленного канала. Windows production-установщик позднее следует
подписать Authenticode; структура папок и формат `latest.json` для этого меняться
не должны.
