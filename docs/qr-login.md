# QR-вход Orex без MAS

QR-вход использует встроенный Synapse endpoint
`/_matrix/client/v1/login/get_token`, временный rendezvous MSC3886 и вход через
`m.login.token`.

Одноразовый Matrix login token **не помещается в QR-код**. QR содержит только:

- адрес временной rendezvous-записи;
- случайный 256-битный ключ шифрования;
- challenge и короткий срок действия;
- адрес homeserver для защиты от входа не на тот сервер.

Rendezvous хранит только AES-256-GCM ciphertext. После успешного чтения и входа
запись удаляется, а экран, который показывал QR, явно переходит в состояние
«QR использован».

## Одинаковый протокол в обоих направлениях

### Авторизованное устройство показывает QR

1. Авторизованное устройство создаёт rendezvous `offer` и показывает QR.
2. Новое устройство сканирует QR и атомарно записывает `claim` через `ETag` /
   `If-Match`.
3. На устройстве, показывающем QR, появляется диалог «Разрешить вход?» с именем
   нового устройства.
4. Только после подтверждения Synapse выдаёт одноразовый login token, который
   помещается в зашифрованный `response`.
5. Новое устройство получает token, входит через `m.login.token` и удаляет
   rendezvous-запись.
6. Показывающее устройство получает `404` при следующей проверке и отображает
   «QR использован».

### Новое устройство показывает QR

1. Новое устройство создаёт rendezvous `request` и показывает QR.
2. Уже авторизованное устройство сканирует запрос.
3. На сканирующем устройстве обязательно показывается диалог
   «Разрешить вход?» / «Отклонить».
4. После подтверждения оно получает одноразовый login token и записывает
   зашифрованный `response`.
5. Новое устройство входит и удаляет rendezvous-запись.

Старые QR-коды, содержавшие Matrix token напрямую, распознаются только для
вывода понятной ошибки и больше не принимаются для входа.

## Обновление, отзыв и срок действия

- QR действует около двух минут.
- При создании нового кода клиент сначала синхронно удаляет предыдущую
  rendezvous-запись, а затем создаёт новую.
- Если старую запись не удалось отозвать, новый QR не показывается: это не даёт
  интерфейсу случайно оставить два одновременно действующих кода.
- После подтверждения входа кнопка обновления блокируется до завершения входа,
  чтобы не удалить уже выданный зашифрованный ответ.
- Закрытие экрана до подтверждения отзывает QR. После подтверждения экран можно
  закрыть, не уничтожая ответ, который ещё должно забрать новое устройство.
- Использованный, отклонённый и истёкший QR визуально заменяется отдельным
  состоянием и больше не остаётся на экране.

## Дизайн QR

QR оформлен в стиле Orex: светлая подложка, медные цвета, квадратные finder-eyes,
круглые data modules и отдельная подпись под кодом. Используется уровень
коррекции ошибок `Q`.

Не помещайте логотип поверх центральных модулей без отдельного тестирования на
разных камерах. Фирменная подпись находится за пределами QR-матрицы, поэтому не
уменьшает её читаемость.

## Поддержка сканера

- Android, iOS, macOS и Web/Chrome: сканирование и показ QR.
- Нативные Windows и Linux: только показ QR; режим сканирования скрыт.

Для браузерной камеры нужен HTTPS и разрешение пользователя.

## Synapse

Добавьте в `data/homeserver.yaml`:

```yaml
login_via_existing_session:
  enabled: true
  require_ui_auth: false
  token_timeout: 2m

modules:
  - module: matrix_http_rendezvous_synapse.SynapseRendezvousModule
    config:
      prefix: /_synapse/client/org.matrix.msc3886/rendezvous
      ttl: 2m
      max_bytes: 4096
      max_entries: 1000

experimental_features:
  msc3886_endpoint: /_synapse/client/org.matrix.msc3886/rendezvous
```

Не создавайте повторные YAML-ключи `modules` или `experimental_features`:
объедините настройки с существующими блоками.

`require_ui_auth: false` убирает повторный ввод пароля. Клиент всё равно требует
явное подтверждение перед выпуском login token. Компромисс этого режима:
украденная действующая Matrix-сессия также способна запросить новый login token,
поэтому важны защищённое локальное хранилище, короткий TTL и управление
устройствами.

Проверка модуля:

```bash
curl -i -X POST \
  -H 'Content-Type: application/octet-stream' \
  --data-binary 'test' \
  https://vasys.ru/_synapse/client/org.matrix.msc3886/rendezvous
```

Ожидаются `201 Created`, `Location` и `ETag`.

## Клиентская конфигурация

Production URL задан в `OrexConfig`. Для другого сервера передайте:

```text
--dart-define=OREX_QR_RENDEZVOUS_URL=https://example.org/_synapse/client/org.matrix.msc3886/rendezvous
```

URL обязан быть HTTPS. Клиент принимает session URL только с того же origin и
только внутри настроенного rendezvous path.

## Безопасность и ограничения

- Любой QR входа является краткоживущей секретной возможностью. Не публикуйте и
  не фотографируйте действующий QR.
- Всегда сверяйте имя нового устройства в диалоге и подтверждайте только своё
  устройство, которое находится перед вами.
- `ETag` / `If-Match` не позволяет двум штатным клиентам одновременно захватить
  один `offer`.
- Login token одноразовый и выдаётся только после явного подтверждения.
- Публичный MSC3886 endpoint не требует Matrix-аутентификации. Ограничьте его
  rate limit на reverse proxy и сохраняйте небольшие `max_entries` и
  `max_bytes`.
- MSC3886 и используемый модуль имеют экспериментальный статус. В будущем их
  следует заменить собственным минимальным Orex-модулем или стабильным
  стандартным механизмом привязки устройств без изменения пользовательского
  сценария.
- После входа E2EE-проверка устройства, cross-signing и восстановление key backup
  остаются отдельным этапом.
